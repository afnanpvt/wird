# Wird - project instructions

## No internal context in public-facing copy

Never let internal conversation context - decisions we made together, reasoning about *why* something was built a certain way, references to a previous design, a rejected approach, or anything from our back-and-forth - leak into anything a stranger will read: README.md, the marketing site (wird-site), Reddit posts, release notes, app store copy, in-app strings, commit messages that get surfaced publicly, etc.

Concretely: don't write lines like "no digging for it in a menu" (a reference to an earlier design we moved away from) or "we changed this because you said X" in public copy. Public copy should read as if written fresh for someone who has zero knowledge of this conversation - describe what the feature *is* and does, not the story of how it came to be that way or what it isn't anymore.

Before publishing any public-facing text (docs, site, social posts, store listings), reread it and ask: "would this sentence make sense to someone who has never talked to me about this app?" If a sentence only makes sense with private context, cut it or rewrite it from scratch.
